CONTEXT & EXECUTION

对话正文只回答了一半的问题。

“说了什么”之外，还要知道模型看过哪些文件、调用了哪些工具、产生了哪些错误、是否分派了子会话。右侧面板把这些证据放回同一条时间线。

FilesContextAudit

三个面板分别回答什么

FILES

使用了哪些材料

聚合会话中的文件与图片引用，帮助你从结论返回输入材料。

CONTEXT

带入了哪些上下文

显示配置文件、context 指令、compact 边界和来源可证实的上下文对象。

AUDIT

执行过程是否可靠

按工具类型、错误、耗时与调用关系检查执行路径；结论是解释性信号，不是客观质量分。

执行树怎么读

  1. 从顶层轮次开始

    顶层节点表示用户/助手轮次或来源保存的执行单元。

  2. 展开工具调用

    查看 Bash、Read、Edit、Write 等调用及其结果；错误需要结合原始输出判断。

  3. 追踪子会话

    若来源保存了 agent/subagent 关系，树会显示分派与返回；缺失关系不会被假装补齐。

  4. 回到正文核对影响

    执行成功不等于结论正确。检查工具结果是否真的支持助手的最终回答。

执行树、Lineage 和 Galaxy 不一样

视图 范围 问题
执行树 一条会话内部 这次执行调用了什么、哪里出错？
Lineage 有继承/续接关系的会话 这条会话从哪里来，后来分成了什么？
会话图谱 / Galaxy 整个 Library 来源、项目和会话群之间形成了什么结构？

可信边界

  • 来源显式保存的字段优先于文件结构重建，重建优先于启发式匹配。
  • 并非每个来源都保存 thinking、子会话、工具参数或完整结果。
  • 路径、附件名和终端输出可能包含敏感信息，分享截图前仍需检查。
  • Audit 中的反模式或摩擦提示用于定位复查点，不是对人或模型的最终评价。
